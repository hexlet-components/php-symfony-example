## Афиша мероприятий на Symfony

Учебное HTML-приложение для [курса Symfony на Хекслете](https://ru.hexlet.io/courses/php-symfony). Посетитель читает афишу, пользователь создаёт мероприятия и редактирует свои записи, администратор управляет всеми мероприятиями. Пример показывает маршруты, Twig, сервисы, Doctrine, формы с валидацией и CSRF, вход и права на отдельные записи.

В корне репозитория находится итоговое приложение. Каталог _.examples/_ хранит состояния уроков. Их можно восстановить отдельно и изучать пример с выбранного места.

## Требования

Нужны PHP 8.5 с расширениями `intl`, `mbstring` и `pdo_sqlite`, Composer и Make. Остальные расширения и зависимости проверяет Composer при установке. Данные хранятся в SQLite, отдельный сервер БД для локального запуска не требуется.

## Быстрый запуск

Из новой копии репозитория приложение подготавливается двумя командами.

```bash
git clone https://github.com/hexlet-components/php-symfony-example.git
cd php-symfony-example
make setup
make start
```

Афиша доступна по адресу <http://127.0.0.1:8000/events>. Порт можно выбрать командой `make start PORT=8001`. Остановка сервера через `Ctrl+C` сохраняет данные в _var/agenda.db_.

`make setup` устанавливает зависимости из _composer.lock_, применяет миграции и загружает учебные данные. Повторный запуск пересоздаёт dev-БД и удаляет внесённые вручную учебные записи. Для одной установки пакетов без сброса данных используется `make install`.

## Учётные записи

Fixtures подготавливают пользователей с учебным паролем `study-password`.

| Пользователь | Email | Возможности |
| --- | --- | --- |
| Alice | <alice@example.test> | Создаёт мероприятия и управляет своими записями |
| Bob | <bob@example.test> | Создаёт мероприятия и управляет своими записями |
| Администратор | <admin@example.test> | Управляет всеми мероприятиями |

Вход находится по адресу `/login`, выход выполняется формой с CSRF-токеном. Для проверки владения можно войти как Bob и попробовать открыть редактирование мероприятия Alice. Ожидается 403. Сервер проверяет разрешение через voter перед изменением записи.

## Проверки

Полный локальный прогон проверяет PHP, контейнер Symfony, шаблоны, YAML и поведение приложения.

```bash
make check
```

Отдельно тесты запускаются командой `make test`, форматирование и статические проверки командой `make lint`. Тестовая БД _var/agenda_test.db_ отделена от dev-БД. Сценарии проверяют CRUD, ошибочные данные, подмену CSRF-токена, вход и выход, права владельца и администратора, переводы, команду и обработчик события входа.

Инструменты форматирования и проверки репозитория объявлены в _mise.toml_. После установки инструментов команда `mise run check` дополнительно проверяет Markdown, ссылки, опечатки и workflows. Хуки ставятся в этот репозиторий командой `hk install`.

## Состояния уроков

Команда из каталога примера создаёт результат выбранного урока в новом каталоге. Существующий путь назначения она не перезаписывает.

```bash
php .examples/prepare.php first-test /tmp/agenda-first-test
cd /tmp/agenda-first-test
composer install
php bin/phpunit
php -S 127.0.0.1:8000 -t public
```

В этом состоянии список строится без БД. После подготовки состояния `migrations` или более позднего перед запуском нужны `php bin/reset.php dev` и `php bin/reset.php test`. Полный список слагов и порядок подготовки находятся в [описании состояний](.examples/README.md).

## Устройство приложения

| Каталог | Назначение |
| --- | --- |
| _src/Controller/_ | HTTP-действия списка, карточки, форм и входа |
| _src/Entity/_, _src/Repository/_ | Сущности Event, Category, User и поиск мероприятий |
| _src/Form/_ | Поля формы мероприятия без принимаемого из браузера владельца |
| _src/Security/_ | Проверка прав владельца и администратора |
| _src/Service/_ | Подготовка краткого описания через внедрённый сервис |
| _src/Command/_ | Команда ближайших мероприятий |
| _src/EventListener/_ | Запись успешного входа в журнал |
| _templates/_, _translations/_ | Twig, русский и английский интерфейс |
| _migrations/_, _src/DataFixtures/_ | История схемы и учебные данные |
| _tests/_ | Функциональные и модульные проверки |

Русский список доступен по `/events`, английский по `/en/events`. Обе страницы читают одни записи. Команда `php bin/console app:events:upcoming 5` выводит ближайшие мероприятия. Успешный вход вызывает обработчик `LoginSuccessEvent`, который пишет сообщение в журнал разработки.

Пример предназначен для локального изучения. Подготовленные пароли, режим отладки и команда сброса относятся к учебной среде. При запуске со своей внешней БД скрипт сброса отказывается удалять данные.
